# V0.9.0 输出约定：交付成品，而不是处理日志

## 两层数据

**阅读层**：本次文体的正文，允许自然内容标题和必要发言者标签。默认不放批次号、逐句时间戳、AI分析、推理、校对清单、可选下一步或反复免责声明。

**来源层**：不删除任何原始转写/译文候选/人工修订；保留时间范围、声音分组、疑点、过滤决定、上下文词语修订和本次合并源ID。界面折叠，审计JSON可导出。成稿历史不原地重写。

移出阅读层不是把不可靠资料变为事实。知识文档应将个人意见归属于讲述者；文字稿保留说话人自己的犹疑、否定、例子和差异。确认缺词也不能随意补事实。

## 模式

| 模式 | 用户获得 | 不应获得 |
|---|---|---|
| 知识整理 | 整篇主题连贯的知识文章，概念/论据/例子/条件按内容需要组织 | 六篇小摘要按“分段1…6”拼接；空模板；把讲述者意见视作事实 |
| 剧本 | 原文支持的场景/事件及角色对白；无场景信息时直接写对话 | 编剧建议；剧情解读；每句都标“动作未交代/请确认” |
| 小说 | 可连续阅读的叙述与对白；按情节衔接 | 大纲、分析、写作指导；默认无证据的画面或心理细节 |
| 文字稿 | 外语发言逐条翻译为简体中文；合并连续同人的发言；补标点、每句换行；保留问答顺序和实质内容 | 摘要、删句、旁白、AI评价；把全片同一人的发言重新集中；将外语原文未经翻译直接作为中文交付 |
| 自定义 | 用户指定文体和格式的成品 | 一律套知识模板；忽略明确的核查报告要求 |

用户选择创作改写时可做有边界文学润色，结果信息一次性标明，正文不反复插改编声明。未明确选创作则不能凭空补人物、场景、证据。

## 实现

1. `readingTurns`只按相邻声音ID/session/time epoch/间距组织资料，不做真实身份推断。unknown/overlap/uncertain不合并。单轮90秒/1400字符为阅读预算，超过则自然分开但仍保留全部源词。
2. 文字稿先将外语发言逐条翻译成简体中文，再做标点编辑。翻译和标点输出均为有顺序ID的JSON，不是自由文章；应用渲染说话人和换行。翻译缺项、ID错位、仍为外语或阿拉伯数字被改动时拒绝发布本次文稿，不得静默回退成外语原文；原始听写保留在来源记录。标点字符/数值/英语词检查不通过时按原字回退，拒绝说明放audit。
3. 知识多块内部取材再统稿，不把map输出直接展示。最终模型仍可能遗漏，需真实样本验收。其他模式前文尾部作为衔接上下文，不作为新资料重复输出。
4. `cleanReaderOutput`只迁出明确处理编号、编辑说明和意外提示词标题；不靠“包含确认/AI”等宽泛关键词删句。不去掉实际章节名。自定义模式保留用户需要的核查结构。
5. `documents[].audit`有上限并独立保存；阅读导出只使用`markdown`；auditExport保留来源。旧版本文档没有audit时继续可读，不伪造历史依据。
6. 原始按采样的完整笔记导出是备份，保留原结构。这与“导出整理结果”用途不同。

## 必须检查的失败场景

模型漏ID/改否定/改数值/英文词拼接、跨session同编号、A-B-A、长暂停与回看、过滤掉B后不能把两条A硬合并、共享取消、无音轨、停止后迟到授权、模型输出内部说明、旧历史选择及导出。程序测试不代替人工听原音。
