# git-r18 升级说明：外语文字稿自动翻译

## 本次修复的问题

用户生成的“文字稿”正文仍出现西班牙语。根因不是 ASR 没有识别到语言，而是文字稿专用生成分支只执行了标点/排版：

1. `readerSourceText()` 会在 ASR 译文失败、关闭或标为 `needs_review` 时，按保护规则回退到原始听写。
2. 文字稿分支原先直接把这些阅读层文字交给标点模型，没有在成稿前再执行独立翻译。
3. 因此即使识别和说话人标签正常，最终文稿也可能保持西班牙语。

## git-r18 的处理顺序

1. 按原始 cue 与说话人 ID 形成连续发言轮次。
2. 将长发言切成有界短片段，识别外语内容；已可信且仍显示为中文的 ASR 译文直接复用。
3. 对未翻译、翻译关闭、失败或待核对的外语片段，逐条调用文字模型翻译为简体中文。
4. 校验 JSON 结构、片段 ID 和顺序、中文内容；原文已有阿拉伯数字时要求译文保留这些数字。拼写数字（如 veinte）允许翻成中文数词或阿拉伯数字。
5. 只有翻译验证成功后，才进入原有标点/断句阶段。
6. 说话人标签、轮次顺序、时间与来源 ID 不变；原始 ASR、原语言和历史文稿不覆盖。

短文路径 `extension/background.js` 与长文路径 `extension/longform-background.js` 均已接入。长文翻译按输入指纹保存检查点；检查点 schema 从 1 升至 2，并将 `language`、`translationStatus`、`needsReview` 纳入指纹，防止复用旧的未翻译结果或语言状态已变化的缓存。

## 失败时的行为

若模型返回非法 JSON、缺失/错位 ID、仍为外语、译文过长或改动原文中的阿拉伯数字，本次文字稿生成会明确失败，不会把原始西班牙语静默当作中文成稿。原始记录和已有文稿保持不变；长文已验证的翻译批次可在重试时复用。

## 升级步骤

1. 先备份当前工程目录。
2. 停止 VideoKnowledge 本地服务（本次只改 Edge 扩展文字稿生成代码，服务端无需重装）。
3. 用本包源码覆盖工程源文件；保留 `.venv`、模型、SQLite、音频缓存、笔记、`ASR_SETTINGS.bat` 等本地数据和设置。
4. 在 Edge 打开 `edge://extensions`，找到原来的 VideoKnowledge 扩展，点击“重新加载”。不要删除扩展或清除扩展存储。
5. 刷新目标 YouTube/B站视频页面，再次选择“文字稿”生成新文稿。历史文稿不会自动重写；新生成结果会新增一份历史记录。
6. 确认摘要/文字模型已配置且可用。若模型输出仍是外语或格式不合格，新版会显示翻译失败原因，不会发布未翻译正文。

## 验收边界

构造模型测试覆盖短文与长文两条路径、翻译失败拒绝发布、数字/ID校验和长文检查点恢复。没有在本次运行环境调用用户实际 Ollama/Qwen 模型，也没有使用截图中的完整视频做双语人工核对。真实翻译的专名、否定、口语残句、数字词及语义忠实度仍需目标机人工抽查；程序校验不能证明翻译语义百分之百正确。
