# VideoKnowledge git-r26：中西混合补译、残句合并和访谈人物自动命名

## 这次为什么 r25 之后仍然有西语

真实反馈截图中的 `Sergio Marina ... guiando数以千计...` 同时含有较长西班牙语与中文结尾。r25 虽然能拒绝将该文本冒充完整中文，但当本地模型多次无法返回合格翻译时，r24/r25 的“保留原文完成文稿”仍然会把该句显示出来；且旧版已经达到尝试次数的检查点会保存失败状态。本次处理的是**模型失败后的自动恢复策略**，不等于声学 ASR 的原句一定正确。

## r26 变更

1. **分段自动补译**：正常先逐条结构化翻译；多次不成功后切换单条纯文本翻译；最后把未完成的长句按安全的原文语段（而不是把原文与任何中文随意黏接）拆成短小片段，分段请求本地模型并重组。最多尝试有界数量，避免两小时视频反复无限续写。保存翻译片段检查点，断点续跑复用已成功的译文。数字、原文保真仍校验，已有合格译文不重复修改。
2. **不把失败当成功**：只有能够确认完整中文的条目才以中文译文显示。如果本地模型一直不能翻译，仍可无人工审批继续生成，但失败片段会以 `〔未译原文：...〕` 明确标识；这不是已经解决的译文，用户无需再审核才能推进任务。
3. **短句合并**：识别相邻、同时间片且有可靠下一位声音承接的极短无归属片段（例如“我们”），自动接入下一段显示；“嗯”等独立应答不猜发言者。原始记录、时间轴、存储的说话人状态不被改写。
4. **访谈介绍后的姓名映射**：若上一段明确用 `Sergio Marina, ...` 加多项职业履历介绍嘉宾，后一位**不同**声纹说话人马上接话，则为后一位使用 `Sergio Marina（根据介绍推测）`。不会把介绍者误认为 Sergio，也不会仅凭正文提到名字强行绑定。仅有文本时不是证实的真实身份；仍依赖声学分组正确性。
5. **短/长视频均处理**：文字稿两条生成路径共用上述逻辑。角色自动命名的检查点 schema 及翻译检查点策略升级；不改原 ASR 文本、SQLite、录音或旧导出文件。

## 升级步骤（Windows / Edge）

1. 停止生成任务，备份 `D:\VideoKnowledge_Git_Project`。
2. 解压完整 ZIP，把 `VideoKnowledge_Git_Project` 下的源码文件按相同目录覆盖到原工程；**不要删除或覆盖自己的 `.venv`、`.venv-qwen`、模型目录、配置、音频缓存、SQLite、笔记**。
3. Edge 访问 `edge://extensions`，找到现有 VideoKnowledge，点击重新加载，再刷新视频页面。
4. 用相同视频重新生成一份**新的**文字稿。旧 r25 导出的 HTML/Markdown 不会因升级自动变化；相同视频的已成功翻译检查点可复用，旧的未翻译保底将再次尝试补译。
5. 此补丁不改服务器端本地 ASR / Sherpa / Ollama 配置，不需要重新下载安装模型。

## 验收

查看 Sergio Marina 那句能否完整变为中文，不再残留 `doctora y filosofía ... guiando`；"我们"是否与后一位发言的主句合并，姓名是否标注给紧接着发言的嘉宾（而不是朗读介绍的主持人）。若模型反复输出无法译成的内容，会看到明确的 `〔未译原文：...〕`，请据此检查上游模型能力，而不是认为软件已成功翻译。完整自动化结果见 `qa/GIT_R26_TRANSLATION_SPEAKER_REPORT.md`。

**边界：** 目前只在容器里用构造数据和浏览器模拟环境测试，未连接用户 Windows/Edge、本地 Ollama、原始视频或声纹 DLL 进行实测。模型语义翻译准确性和说话人真实身份不可由本轮构造测试证明。

## 回退

保留本次 ZIP；若需要回退，先备份当前数据，再恢复 r25 源码并重新加载扩展。新旧原始听写、录音和先前导出文件均不删除；在 r25 下打开新版本未完成翻译检查点可能重新生成，不推荐清空任何旧数据。
