# git-r28 升级说明：访谈人物自动命名与翻译指令回显防护

## 用户反馈与修复范围

r27 的文字稿中出现了 `Sergio Marina（根据介绍推测）`、`说话人3`，即使 Sergio 向“玛丽安”直接致谢也没有把其姓名关联到对方。同时，个别生成结果混入了 `请把下面标签内的发言准确翻译……` 之类内部模型提示。

## 修改

1. 人物姓名直接显示在正文标题：新生成文字稿中 `Sergio Marina` 不再附加“根据介绍推测”，旧传入的标签也在展示/清洗时移除这一后缀。内容角色仍保留为内部元数据，不变更原声纹编号。
2. 增加**对话称呼**姓名关联：`感谢你，玛丽安` / `谢谢你，玛丽安` / `Thank you, Mary` 等明确称呼指向交谈对象，**不是**说出这句话的人；使用近邻声纹轮次检查，并拒绝前后出现两个不同候选者的歧义映射。普通第三人称提及不作为身份。支持原文与中文译文中的称呼，优先采用中文显示名称。
3. 长短文两条文字稿路径共用说话人标注器；本地角色分析将明确称呼作为一种可接受证据，保存到原有 `speakerNames`/`speakerEvidence`（`direct_address`）。缓存 schema 从4升为5，原始声纹/音频/旧文章不改写。
4. 翻译结果如果回显了扩展内部翻译命令，视为无效译文并自动重试；旧检查点中的这种“成功”行也会重新校验，不能把模型指令当视频正文。正常的专有姓名、阿拉伯数字以及真正的中文正文仍按原规则处理。并非承诺模型输出的所有幻觉都能被静态规则识别。
5. 自动决策，无需用户逐条核对。证据与原始文本保留在内部元数据；遇到多个候选说话人或不同名字互相冲突时保留原标签，不强行编造身份。

## Windows / Edge 升级

1. 停止正在执行的生成任务，备份 `D:\VideoKnowledge_Git_Project`。
2. 解压完整 ZIP，**按相同目录合并覆盖源码**（不要删除当前目录）。保留 `.venv`、`.venv-qwen`、模型、SQLite、音频缓存、私人配置和已经生成的笔记。
3. 访问 `edge://extensions` 并重新加载现有 VideoKnowledge 扩展，刷新原视频页面。
4. 使用同一视频、同一整理设置重新生成**新文字稿**。之前已导出的 HTML/Markdown 不会被静默覆盖。已完成、仍合格的翻译缓存可以复用；被判定回显内部提示词的旧译文会失效并自动请求重译。
5. 不需要重新安装 Sherpa 或 Ollama，不需要清空录音/笔记缓存。

## 测试与限制

在当前容器中进行了模拟多轮访谈、模型失败时的姓名自动存储、缓存有效性、提示词回显以及完整生成入口的测试，并运行仓库单元检查。相关测试日志见 `qa/GIT_R28_DIALOGUE_SPEAKER_TEST_REPORT.md`。

**未进行** Windows 原生 Edge 与真实两小时视频、Ollama 模型推理、Sherpa 声纹聚类对照的现场验证。若声纹本来被分错，或只有一个名字但有多个可能被称呼者，单靠文字无法保证身份正确；程序不会把不明确的关联硬写成事实。

## 回退

恢复 r27 工程源码并重新加载扩展即可；原始字幕、音频、已存笔记不因本次覆盖升级被删除。`speakerEvidence` 新增 `direct_address` 元数据；旧版可能忽略它，但仍能读取原存储的姓名。保留当前备份以便需要时恢复。
