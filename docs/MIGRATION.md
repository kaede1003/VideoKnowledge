# 从补丁目录迁移到Git工程

## 把工程提交Git与让Edge改加载目录是两件事

安全做法是先把本包解压到新工程目录，建立Git版本管理；原插件仍从原路径运行。验证开发版本后，再把必要源码复制到原部署目录，保留原扩展ID、配置和数据。不要一边迁移一边卸载原插件。

也可以在原部署目录中初始化Git，但先复制本包的`.gitignore`与检查工具，再检查暂存区。`.venv`、`ASR_SETTINGS.bat`、模型、录音和数据库不能提交。本包不附带旧目录的运行数据。

## 升级操作

1. 导出重要笔记、所有需要保留的成品和核查JSON；确认下载文件能打开。
2. 停止采集，尽量等已确认缓存处理完成，再停止本地服务。
3. 备份旧源码和本地配置到仓库外。不要删除浏览器存储/SQLite缓存。
4. 将选定版本的`extension`、`server`和必要脚本复制到原部署目录，不覆盖`ASR_SETTINGS.bat`。
5. 启动一个本地服务；重载原扩展、刷新页面、重新打开设置。当前对应扩展0.7.2/服务0.7.1/协议5。
6. 短样本验证配置、记录、停止、旧笔记、导出，再用于长节目。

## 注意

更换未打包扩展的加载路径或安装副本可能改变ID；本地Ollama精确来源许可也随ID关联。新副本不能假设自动获得旧数据。当前核查JSON用于审阅，不要在没有实现导入功能前承诺它能一键恢复所有数据。

数据迁移只做增量兼容，不在未知队列状态下删除PCM。截图和日志可能含本地目录/节目链接，提交前检查。新Git目录没有模型权重不是丢模型：模型通常由已有缓存和本地服务保存，不能复制到Git。

## 回滚

停止新采集；保留新增导出和未完成缓存；恢复仓库外备份的源码并重载同一扩展。涉及数据库结构的新版本必须有明确兼容检查，不能盲目降级后删表。当前git-r1只整理工程，不改业务结构，不需要数据迁移。
