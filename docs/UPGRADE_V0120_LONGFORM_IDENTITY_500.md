# V0.12.0 · 长视频分层整理、角色姓名证据推理、视觉 HTTP 500 隔离

## 本次实际变更

- **长文自动分流**：当当前视频的选定文本估算超过约 4300 tokens，使用独立长视频生成流程。源记录按约900 token 的安全块切分，知识模式先逐块取证再做层级主题索引，按章节生成完整正文；文字稿仍逐段保留原话，不做多级摘要；剧本/小说/自定义按原顺序生成相应形式的正文。输出按章节限制 token，在 `finish_reason=length` 时继续写剩余内容。
- **持久检查点**：按 `视频ID + 选定原文及修订指纹 + 模式 + 模型` 持久化到原扩展的 `chrome.storage.local`，每成功一步写入，失败/cancel 后不推进成功状态。相同来源、模型、范围、修订不变时再次点「生成整理」，可续写当前检查点。改动原笔记或范围会生成新指纹，不用旧检查点冒充最新输入。完成状态仅在来源记录 ID 完全覆盖已处理单元、全部章节结束后设置。来源覆盖是数据流程覆盖，不是逐句语义正确率或事实核验。
- **姓名候选**：`VknSpeakerIdentity` 对本机保存的声音分组结合自我介绍或同时间字幕开展本地文字模型推理。必须引用具体原句/字幕、来源 ID、时间；自报姓名可绑定该音频声纹编号，字幕姓名标签至少需要两个不同记录作为证据。剧情旁白、他人称呼或仅画面出现姓名不自动绑定，作为候选供核查；自动姓名不等于真实身份。仅在用户打开角色栏或必要的周期事件时检查，补全增量游标，不重复分析已核查记录。需要声音分组组件可用。
- **视觉500隔离**：原先 `qwen2.5vl` 带 `format:'json'` 的视觉字幕请求触发某些 llama.cpp JSON Grammar 路径异常。视觉请求不再设置强制 JSON Grammar；改由文本指令要求 JSON，返回后仍严格解析两个字幕帧和索引。视觉 HTTP5xx/空回答/错误 JSON 一律不合并为可信字幕，听写服务独立运转。LoRA筛图同样不强制 Grammar。文字稿标点的结构化请求仅在后端错误明确包含 grammar/GBNF 特征时允许**单次**无格式重试，仍严格验证原文不改字、数字不变。

## Windows 升级步骤

1. 停止听写、关闭正在进行的文稿生成，导出重要笔记；等待音频缓存保存，然后运行 `STOP_LOCAL_ASR.bat`。如有进程未退出，先核实端口 8765 所属的本项目进程，不要一键杀掉所有 Python/Ollama。
2. 解压本版升级包，把压缩包内部文件合并覆盖到既有 `D:\VideoKnowledge_Git_Project` 根目录。**不要卸载原 Edge 扩展、改加载路径或删除 `.venv`、`.venv-qwen`、模型、笔记、SQLite/PCM、`ASR_SETTINGS.bat`、`asr_profile.local.json`。**
3. 启动 `START_LOCAL_ASR.bat`；在 `edge://extensions/` 重新加载同一个 Edge 扩展并刷新视频页。`/health` 与扩展面板都应显示 **0.12.0**；安装器仍 **0.8.4**，音频协议仍为5。
4. 在同一视频生成长文前，可暂停听写以冻结原文快照。长视频出现截断/网络错误时，不要清除浏览器存储；修复模型后回到同视频、同范围与模式重新点击「生成整理」即可尝试恢复。
5. 若声学模型尚未安装，按旧指令 `INSTALL_ALL.bat -Profile speaker` 安装并重启服务。Ollama Qwen3-ASR 不用重新下载。

## 质量及限制

- 这版仍不能声称“无限长”：单条模型输入有预算、单章节正文和单文档有上限（1,000,000字符），实际有50,000条原音记录的本地数据库容量保护；超出时报告错误，不静默删内容。浏览器存储可能增长，后续需要检查点归档清理策略。
- 本版尚未在用户 Windows Edge + 真实 Qwen2.5/Qwen3-ASR + 长视频上完整运行。单元测试与模拟浏览器测试不能替代现场验收。
- HTTP 500 来源不能仅凭状态码确定；**本次可访问的 `server.log` 为较早版本**，其中确实记录视觉模型 `Unexpected empty grammar stack` 和 `llama-server exit 1`，但尚未收到更新后的新日志。未来若再次报500，请附最新 `server.log` 的报错时间附近几十行，以及本地视频笔记界面的报错类型，检查前可遮挡本机路径。
- 文稿的“覆盖率”指每个来源记录进入处理流程，不证明 AI 没有在章节中省略细节。字幕比对不是听音核验；自报姓名也可能被 ASR 误听，应保留可回看来源。
- 文字稿不会做知识摘要；脚本/小说/知识模式按照原来的产品定义保留正文形式。历史文稿快照不自动改写。旧小任务仍可能走原来的单次非流式整理路径。真实模型可能重试或出错。

## 回退

如需回退，将此前 V0.11.4 源码包的 `extension` 和 `server` 代码覆盖回原工程（停止服务后进行）；**不要回退或覆盖用户存储目录**。已保存的历史笔记格式继续兼容，V0.12.0 独立检查点可保留，不会自动成为旧版的正文。
