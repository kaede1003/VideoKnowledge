# V0.12.1 自动剧情声线角色分类：升级与验收

## 背景

以前的 `sherpa-onnx` 仅将声音分成 `说话人1 / 2 / 3` 等编号；字幕姓名审查器只核对直接自我介绍和重复同步姓名标签；核心代码只能自动认出自报“主持人/嘉宾”，没有“旁白/系统播报/剧情角色”的语义分类。这个版本**不重新训练声学模型**，而是在已经成功分组的声线上加一层本地语义分类。

## 改动

1. `extension/speaker-role.js` 新增纯函数：按稳定声纹编号汇总多个时间点的原话、筛选代表片段、构造本地模型角色推理请求、校验两个不同记录ID与逐字引文、保留冲突。
2. `extension/identity-background.js` 在原姓名审核基础上另行推断剧情类型。只使用已配置的本地 Ollama 文字模型，**不发送音频和声纹向量**。模型返回的证据必须准确引用原记录，不得仅凭说话人的音高或配音风格推断人物身份。
3. `extension/content.js` 每有新声纹发言记录就排队检查，至少4条有归属记录后启动，间隔不小于45秒；单条视频以自身的隔离键保存推理状态，切视频不串稿。展示“剧情旁白（推测）·说话人1”以及来源依据；不需要手动录入。
4. `extension/core.js`/`background.js` 持久化 `speakerRoles` 与可审计的角色候选；保留已有 `speakerNames`、原始听写、字幕与生成文档。

## 安装

停止正在写入的听写、备份重要笔记后，将本升级包中的文件按原相对路径合并到 `D:\VideoKnowledge_Git_Project`；不要卸载扩展，不要清空扩展存储或 `.venv`。在 `edge://extensions/` **重新加载原扩展**，刷新视频页。服务仍为 0.12.0，不需要重新下载 Ollama/Qwen 或重新启动安装器。

已加载的旧笔记，只要包含有效的声纹编号和至少两条同一声音的可用转写，也可以在展开角色栏时尝试重新分类；**没有声纹编号的纯文字历史笔记不能仅凭文字重建音频身份**。

## 正确理解

- `说话人N` 是声学模型推断的相似音色组，不等于真实人物。
- `旁白/系统播报/剧情角色` 是本地模型依据多句台词的**语义功能推断**，不是专门训练过的旁白/系统音色识别模型。系统音可能没有“任务/宿主”等词，此时仅凭文字仍可能无法判断。
- 同一配音演员可能扮演多个角色；强行分组会出错。角色名只从明确自报或可靠字幕建立；无法确认时保留中性编号。
- 当前写好的文字稿与摘要**不会自动重写**；重新生成时才使用新标签。
- 文字模型没有配置、输出格式不符、可靠说话人区间不足时，不应猜标签，也不阻止 ASR。

## 测试与人工验收建议

在真实 Edge 和已安装 `INSTALL_SPEAKER_MODEL.bat` 组件的机器，选一段旁白-系统-人物轮流讲话且有明显声线差别的视频。确认声纹编号在同一视频多次重复时保持稳定，字幕姓名不会冒充声纹；新记录累积后约几十秒能看到 **推测类型** 或明确的“仍待确认”状态。录音、翻译、视频缓存和笔记均不能因为分类失败丢失。

自动分类质量与角色姓名正确率需要原视频人工标注进行评测，当前没有真实视频端到端质量数据。
