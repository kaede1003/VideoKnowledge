# git-r21：长文整理 HTTP 403 诊断修复与升级

## 本次从 r20 源码确认的缺陷

截图中 `AI_HTTP_403：长文整理请求失败，检查点已保留` 来自 `extension/longform-background.js` 的 HTTP 非 2xx 分支。**403 表示目标聊天服务拒绝该请求**，并不能仅凭 403 判定是文字太长或某个模型出故障。r20 缺陷在于：长文统一错误消息，不复用普通聊天的本地 Ollama `Origin` / 自定义接口权限提示；设置页的连接检测只做 `stream:false` 的普通请求，长文实际使用 `stream:true`，因此可能出现“模型验证正常，长文仍 403”。

本次修复是准确诊断与验证，不会绕过鉴权或承诺自动解除上游拒绝。

## 新版变更

1. 普通与长文请求使用统一错误分类：本机 Ollama 403 提醒检查本扩展来源 `OLLAMA_ORIGINS`；自定义服务 403 提醒核对令牌/模型权限/额度/内容策略。404/413/429/5xx 各有不同提示；HTTP 403 不自动重试、取消鉴权或切换服务。
2. 设置 →「阶段摘要与手动深度整理」→**保存并验证普通/长文请求**，先发固定短文本的普通聊天，再向相同的接口、模型与凭证发送固定短文本、`stream:true` 的请求；两项成功才显示通过。标注服务返回 SSE 或 JSON。测试不会发送任何视频原文或检查点。
3. 只使用上游响应的安全格式 `x-request-id`/`x-correlation-id` 以帮助查服务日志。不会把 API Key、带查询参数的 URL、模型输入和错误正文输出到提示信息。
4. r20 的检查点分片、失败续跑、翻译、说话人身份与实时页面优化保持不变，**不会因为 403 删除任何已有数据**。

## Windows 原位升级

1. 停止生成/听写，备份原工程；将 r21 ZIP 解压并合并覆盖原项目源码。**不要删除** `.venv`、`models/`、`.venv-qwen`、`ASR_SETTINGS.bat`、音频缓存、SQLite 和笔记。
2. 在 `edge://extensions/` 对**原有** VideoKnowledge 扩展点击“重新加载”；刷新原视频网站。**不要删掉扩展重装，扩展 ID 改变可能导致原存储不可见。**
3. 打开扩展“设置” →“阶段摘要与手动深度整理”，先读出“实际接口地址和模型名称”，点击**保存并验证普通/长文请求**。
4. 如果两种通道均通过，返回原视频，在相同模型/范围再次点击“生成整理”，可复用 r20 的检查点。长视频的真实成功率仍需实测。

## 如果仍报 403

- **本地 Ollama（接口为 `http://127.0.0.1:11434/v1/chat/completions`）**：403 常见于来源限制，也可能是代理或其他服务在 11434 上返回。打开本扩展设置页的 **「本机 Ollama：不需要 API Key」→「复制仅允许本扩展的命令」**；在 PowerShell 中执行该**精确扩展 ID** 的命令。手动**完整退出** Ollama，然后重新启动使新环境变量生效。它只追加当前扩展来源，不设 `OLLAMA_ORIGINS=*`，不修改全局监听地址。运行 Ollama 作为服务或从不同用户环境启动时，请向管理员确认其启动环境变量。再次点击“保存并验证”。
- **自定义 HTTPS 聊天服务**：检查账号令牌是否有效、是否有模型及流式聊天使用权限、账户额度，以及平台内容政策。若只有长视频被拒绝，检查提供商的 `x-request-id` 对应日志与输入容量限制。不要通过无意义的重复请求来尝试绕过服务策略。
- **区分阶段**：连接测试失败说明固定短文本即被拒绝；连接测试通过但原两小时长文仍报 403，说明与具体长文请求（长度、额度/策略或请求过程）有关，需要在该提供方日志核查。不能仅据 403 断言“模型上下文太小”。
- 如果仍有问题，提供**已脱敏**的“摘要接口类型（本机/自定义）、模型名、验证结果和出错阶段、403 对应时间”，以及服务方日志中与该时间对应的错误类别。**不要提供 API Key、完整私有地址查询参数或用户私人音频内容。**

## 测试与边界

新增普通聊天成功但长文 `stream:true` 403 回归、SSE/JSON 兼容、413/429/500、敏感错误正文不泄漏、r20 检查点续跑等自动化测试。没有联网调用你的 Windows Ollama、自定义服务或真正两小时的原视频；因此不能宣称现场 403 根因已修复。需要在真实环境通过设置页双通道验证，并对原视频续跑验收。

## 回滚

恢复 r20 的源码并重新加载**同一扩展**，保留 Chrome Storage、模型及数据库。r21 不升级检查点格式，也不做数据迁移；旧 r20 检查点可继续读取。
