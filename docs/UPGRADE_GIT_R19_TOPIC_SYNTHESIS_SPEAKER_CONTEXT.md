# git-r19 升级说明：知识主题合并与上下文角色命名

本版以 git-r18 外语文字稿翻译版为基线，保留 r16/r17 的 Sherpa 子进程隔离、Sherpa 1.13.8 版本门槛、Ollama ASR 音频保留和 r18 翻译流程。

## 本版解决的问题

### 1. 知识文档重复主题

旧长文路径先按采集窗口生成章节草稿，再直接拼接章节。即使前后两章讲的是同一个主题，也可能分别生成重复标题和重复解释。短文路径虽有最终统稿，但提示没有足够明确地要求建立唯一主题目录。

本版改为：

- 短文知识模式：强化最终统稿规则，按语义主题而不是采集时间顺序重组。
- 长文知识模式：章节草稿生成后增加递归主题合并阶段；每轮输入有 token 上限，输出作为下一轮输入，最终形成单一知识文档。
- 输出结构要求为一个主标题、多个大主题、每个大主题下按需建立小主题。
- 同一主题重复出现时合并定义、解释、案例和结论；独特数字、例子、条件、反例及不同讲述者立场仍需保留。
- 观点与事实分开，不将不同人的意见合成共识。
- 新增独立合并检查点；中断后可续跑。长文检查点版本由2升为3，避免复用旧版未执行主题合并的结果。

### 2. 说话人命名和角色准确性

旧角色分类主要看同一声音自己的几句台词，容易缺少主持人与嘉宾、提问者与回答者、剧情人物与旁白之间的上下文。

本版改为：

- 每个采样台词附带前后相邻对话，角色模型综合多段台词和上下文判断。
- 除粗分类外，可输出受证据约束的内容称呼，例如“访谈主持人”“受访专家”“提问者”“医生”“母亲”“主人公”“系统播报”等。
- 内容角色称呼和真实姓名分开保存；显示称呼必须匹配受限的角色词尾，不能把随意生成的人名当作角色名。
- 主持人/嘉宾分类需要相邻对话或明确自述依据，减少仅凭一句问句就判为主持人的误判。
- 姓名识别增加一条保守路径：前一位不同说话人明确欢迎/介绍嘉宾或角色，且当前声音紧接回应时，可将介绍中的姓名作为候选绑定；仍需检查原文，第三人称随口提及和普通称呼不自动绑定。
- 姓名自我介绍识别扩展到西班牙语、法语常见表达。
- 角色分析缓存版本升级，旧角色会重新检查；姓名分析缓存也会重算上下文变化。

## 升级步骤

1. 停止 VideoKnowledge 本地服务。
2. 备份当前工程目录。
3. 解压本版本，覆盖原工程源码。
4. 不要删除 `.venv`、`.venv-qwen`、`models`、SQLite、笔记、音频缓存或 `ASR_SETTINGS.bat`。
5. Edge 打开 `edge://extensions`，找到 VideoKnowledge 并点击“重新加载”。
6. 重新打开目标视频，展开“自动识别声音与剧情角色”，等待本地文字模型完成上下文分析。
7. 对知识文档选择“知识文档”并重新生成。旧文稿不会被自动改写。

本版没有新增 Python 依赖，不要求重新安装 Sherpa 或 Ollama 模型。主题级最终合并会额外调用本地文字模型，长视频耗时和 token 消耗会比 r18 增加。

## 准确性边界

- 主题去重是模型编辑，不是形式化证明；仍需检查关键数字、因果、专名和争议观点。
- 内容角色称呼是基于转写文字及邻近对话的推测，不是声纹身份认证。
- 如果 Sherpa 声学分组把两个人合并，或把同一人的声音拆成多个 speakerId，文字模型不能可靠修复底层声纹分组。可用面板中的人工说话人归属修正。
- 只有本人自报、明确紧邻介绍后接话或可靠同步字幕才自动绑定姓名；证据不足时仍保留中性编号。
- 当前自动化测试使用合成/模拟模型响应；真实 Ollama 模型对整段视频的主题合并质量、角色准确率和 Windows 实机体验仍需用户验收。
