## 已复现的旧行为（构造测试，不是用户视频引文）

1. 在旧 `text_enrichment.validate_translation` 中，`It is not true.` → `这是真的。` 会通过，因为只检查中文与数字；漏掉的否定没有检测。
2. `It might be a mistake.` → `这就是一个错误。` 同样会通过。
3. 旧字幕清理 `x < 5 and y > 3` 输出 `x 3`。新测试要求完整保留比较表达。

回归例只是证明存在代码缺陷/防护缺口，不能证明用户截图中的每一处错误都来自这些路径。

## 未完成的核查

- 当前检索及附件列表没有用户所说的完整笔记文件、这次错误截图的可读取原件或原视频/链接；不能对每个时间戳做逐句原音比对。
- 没有执行真实faster-whisper（当前环境未安装该包）、真实Ollama翻译或真实说话人模型。
- 没有用户Windows Edge原生tabCapture、模型冷启动、GPU/CUDA性能或持续长时间测试。
- 没有字错率、词错率、否定/实体准确率的实际改善数据，不能给出提高百分比。
- 12秒窗口与启发式阈值是工程选项，不是已校准/已优化的最终值。
- JSON结构约束仅规范返回字段，不证明翻译语义正确；词项告警会误报/漏报。
- 标为待核对的原始听写仍可能被下游模型误用；提示和结果告警不是事实正确性保证。
- 旧音频处理后已清理的PCM不能从文字恢复；这版不能自动“重听”全部旧笔记。
- Windows BAT仅做ASCII/CRLF及静态检查，未在Windows本机执行。
- 长文多块生成未做全文文学一致性评估，MV3后台生命周期风险仍存在。
