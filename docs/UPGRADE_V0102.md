# V0.10.2：下载状态与跨视频阅读修复

扩展 **0.10.2** / 本地服务 **0.10.2** / 安装器 **0.8.1** / 协议 **5** / git-r7。
基于本会话已交付0.10.1/git-r6源码修改，没有换用尚在调研的Qwen3-ASR，没有修改100秒长文等待算法。

## 两个问题的证据

### 下载失败不等于一定没登录

原代码固定cookiefile=None/cookiesfrombrowser=None，本机下载请求是匿名的。Edge登录不会自动传给独立Python进程。

另一个确定的代码缺陷：`server/video_download_worker.py`同时设置`max_downloads=1`并直接调用`YoutubeDL.extract_info(...,download=True)`。yt-dlp可在第一项下载处理完成后抛出`MaxDownloadsReached`，原代码的通用错误分支把它报成来源拒绝。本版删除冗余数量限制；单个规范视频URL和noplaylist仍限制单视频，不扩大到播放列表。**用户截图20MiB后失败与该机制相符，但没有现场异常/依赖版本记录，不能声称它是用户这次唯一原因。**

新代码分开提示登录要求、会话过期、403、429、缺JS运行时、EJS失败、缺格式、FFmpeg、网络及未知错误。不因某种异常就接受一个.part文件或跳过完成验证。失败仍保留传输量用于解释，但不显示活动下载进度条；传输了20MiB不代表有可用缓存。

### 完整阅读打开上一视频

原切换流程保留旧session等待新笔记载入，key可能已经指向新页；用户在轮询前点击完整阅读、连续快速切换或迟到回调时，旧正文可被打开。本轮在旧代码中用合成DOM复现了该问题。

修复包括：切换时立即隔离旧状态/旧结果；每次加载用代号识别过期返回；打开、生成、保存、复制和导出前检查真实当前视频key；保存使用源会话快照；生成成稿绑定视频key、URL、标题；渲染签名包含来源和正文哈希；完整阅读冻结当前选中的成稿，并显示视频来源/文稿编号/生成时间。载入失败不显示上一个视频。

**历史已混入的内容不能靠更换标题修复。** 旧记录和成稿不删除、不猜测迁移；请先备份，再核对当前视频原始记录和选中成稿，必要时重新生成。已经打开的旧阅读窗口本来就是旧快照，不会随播放页跳转自动换成新正文，关闭后从当前视频重新打开。

## 更新步骤（原目录保持不变）

1. 导出重要笔记，暂停视频，停止采集并尽量等缓存补录；运行原工程`STOP_LOCAL_ASR.bat`。
2. 把升级ZIP里的全部文件/子目录合并覆盖原工程根目录，例如`D:\VideoKnowledge_Git_Project`。不能套成`extension\extension`。不卸载扩展，不改变加载路径，不删除`.venv`、模型、数据库或`ASR_SETTINGS.bat`。
3. 运行`START_LOCAL_ASR.bat`或`START_ACCURATE_ASR.bat`，只开一个；检查服务版本0.10.2。
4. 在`edge://extensions/`重新加载原插件至0.10.2。刷新所有视频页，关闭旧缓存管理页并重新打开。
5. 新增的`cookies`为**可选权限**；普通听写/整理/匿名下载不需要授予。只有点击登录重试并确认时，浏览器才申请它。
6. 无需重新下载语音或文字模型。缺少下载组件时运行已有`INSTALL_ALL.bat`补齐。若仍提示旧解析组件或缺EJS，可停止服务后只更新本虚拟环境的下载包（见下），不升级所有Python依赖。

## 建议先匿名重试

在视频面板“本地缓存”里，对失败项点击 **重新下载（不使用登录）**。它基于原任务保存的URL新建尝试，不复用其他视频链接，不偷偷用账号，原失败项保留便于对照。已经完成且未过期的缓存不重复下载、不续期。

若实际错误是**需要登录**，可再使用 **授权本次使用YouTube登录重试**：

- 仅缓存管理页可发起。你先确认这一次用途，再允许Edge的可选Cookie权限。
- 后台只读取同一Edge配置里YouTube站点的允许会话字段；不读取密码、Google或其他站点的Cookie，不扫描浏览器数据库，也不让你导出/上传Cookies。
- 会话只传给`127.0.0.1`下载服务、通过子进程标准输入进入内存Cookie容器，随后按域限制用于向YouTube请求。不发送给AI模型，不写Cookie文件、缓存数据库、诊断报告、命令行或正文。
- 默认不开启账号下载；每次重试都需确认。任务完成/失败/取消/退出后释放引用，排队超10分钟不使用旧授权；这是引用清理，不是保证物理内存安全擦除。
- 缓存页 **撤销登录访问权限** 阻止后续读取。已经提交的任务需要另点“取消下载”；撤销不能收回已发送的网络请求。
- 同浏览器别的配置、无痕或其他浏览器登录不等同于当前扩展可取得会话。YouTube可能轮换会话、限制账号请求；账号下载有被限流/封禁的风险，非必要不用。不反复自动用账号重试，不保证授权后所有视频都可下载。
- 不处理DRM、会员/付费或私有视频，不关闭TLS验证，不绕过保护。

## 下载依赖检查（只在有缺项/解析错误时）

缓存页显示yt-dlp、EJS、JS运行时和FFmpeg的检测状态；检测到文件/版本不等于真实网站解析通过。

```powershell
cd D:\VideoKnowledge_Git_Project
.\STOP_LOCAL_ASR.bat
.\.venv\Scripts\python.exe -m pip install --upgrade "yt-dlp[default]"
.\START_LOCAL_ASR.bat
```

需要FFmpeg/Deno时继续使用原`INSTALL_ALL.bat`，不是再新增安装入口。EJS/格式/403/网络限制与是否登录是不同问题。429时停止重复尝试；不要清空全部模型/笔记作为下载修复。

## 缓存与数据范围不变

完成后起算72小时；最高720p，单视频4GiB、总缓存20GiB；服务启动及每15分钟清理。服务关闭/文件占用会延后物理删除，不删除笔记、模型或目录外副本。升级不恢复旧版已经清除的失败媒体文件，也不恢复未采集的原音。

## 本机验收

先选择允许保存的短公开视频匿名下载，看到ready后播放；失败读新的具体错误码。确需登录再逐次授权，并检查撤销后不能再次读会话。只提供错误码和组件版本，不分享Cookie、账号目录或包含签名地址的完整日志。

阅读：视频A生成→站内直接切换B，在B加载前后点完整阅读；不得出现A。连续A→B→C、B加载失败、同时开两页、切回A，检查各自正文/来源编号对应。未生成B结果时显示未生成，不回退A。预览/完整阅读/复制/导出应一致。
