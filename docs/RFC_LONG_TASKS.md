# RFC：可恢复的长文整理任务

**状态：提案，未实现。对应VK-003至VK-007。** 这里的新状态/API/表结构不是当前0.7.2已经具备的功能。

## 为什么需要

现状是MV3后台长函数＋非流式单请求100秒期限＋内存分块数组。只增加时间或过滤部分文字，无法解决后台生命周期、已完成块丢失、取消歧义及任务争用。

## 推荐方向（需任务审阅后冻结）

让本地服务管理持久整理任务，扩展只负责创建、短轮询/订阅进度、取消和展示成品；保留用户明确配置的远端模型时，要另行设计凭据保管和数据授权，不把它自动搬到本地服务。

任务状态：`queued → preparing → running → succeeded`，另有`cancel_requested`、`cancelled`、`failed`和可恢复失败。记录状态修订号与输入快照；外层“停止采集”不等于取消这个任务。所有取消仅针对本项目任务，不终止全局模型进程。

## 数据提案

`jobs`：任务ID、视频会话、模式、时间范围、规范化输入哈希、来源版本、筛选快照、提示版本、模型与参数、状态、创建/更新时间、错误类型。

`job_chunks`：任务ID、块编号、来源记录ID/时间范围、输入哈希、状态、开始/首字/完成时间、输出摘要、用量统计、重试次数。

`job_events`：单调事件序号、任务ID、阶段与可公开进度。不得在默认日志保存原文、API Key或完整响应。

`job_result`：只有全部预期块完成并经过格式/覆盖检查，才原子发布新成品；失败保留上次成品和已完成块，不伪装整份成功。更改原文/修订/主题/模式/模型/提示版本后使不兼容检查点失效。

## 流式与期限提案

适配本地原生NDJSON及已配置的兼容聊天SSE，正确处理跨UTF-8边界、空分块、错误帧、缺终止帧和取消。把首字等待、连续无进展、总任务预算分开；正常持续输出超过旧100秒不应被同一死线中断。具体阈值经VK-002测量后确定，不在此填保证值。

按模式设明确输入/输出预算。知识整理可先抽取可追溯证据再统合；文字稿/剧本不能靠静默截断尾段省时；小说要区分忠实整理和创作润色。进度显示块范围及已完成数，而不是猜测剩余分钟。

## 接口草案，不是现有服务

建议的创建/查询/取消/事件接口置于版本化任务命名空间，例如`/jobs`与`/jobs/{id}`。必须先审查Origin、会话授权、重放和凭据边界；不能仅因为监听回环就认为安全。不得接受任意文件路径、任意URL或全局进程控制请求。

## 调度

本项目自己的翻译、主题分类、视觉与完整整理有可观察队列和预算。深度整理期间可让低优先级可选分类退让，但不能无提示停止采集或丢音频。真实Whisper处理与LLM处理资源不同，应依据测量而不是一刀切串行；其他软件的模型负载不可由本项目保证。

## 验收

AC-016/017/018：正常流超过100秒、首字慢、半途中断、后台重启、重复点击、取消、修改来源后续跑、模型缺失、旧成品保护。先用可控模拟流测试状态机，再用实际Windows Edge/Ollama长文本验证；保持紧凑界面。

## 回滚

新任务表使用独立增量迁移；旧音频队列与笔记不能删除。可回退到旧手动模式但必须显示其限制。通过真实验收前不能移除原始证据与旧功能入口。
