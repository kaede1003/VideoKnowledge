# git-r24 · 外语文字稿自动补译与无人工审核阻断

## 为什么 r23 仍出现 `AI_TRANSLATION_INVALID`

用户实际看到 `8条发言中仍有7条未获得可靠中文译文，最早缺失ID为turn-4`。r23 的翻译逐行保存逻辑虽然能保留合格译文，但连续四次返回缺项/错误 JSON/未译或数字冲突后，仍直接抛错，导致全份文字稿不能交付；历史检查点同时保存耗尽的重试次数，升级后可能立刻再次报错。

## r24 处理策略（自动执行，不需要人工逐条审核）

1. 先按原 ID 批量请求中文翻译。只复用已通过结构、中文内容与数字保护的条目，绝不覆盖原始 ASR。
2. 仅对缺失/异常条目重试，分批缩小：8 → 4 → 2 → 1。
3. 当格式化 JSON 连续失败、请求收敛到单条时，改为**不要求 JSON 的纯中文译文请求**，由模型直接给出一条中文结果。仅因请求确实只有一条，才允许把无 ID 的译文绑定到这条原文；绝不在多人/多条回答中按位置猜配。
4. 每条使用有限请求次数。即便模型最终没有提供任何可用中文，也不因该项拖垮整份文稿；对应句子**保持原语种**，生成详情自动记录数量、未成功翻译这一事实。不用人工点击“核查”或决定是否继续；保留发言顺序、说话人和来源。
5. 原语种句子不能标记为“已翻译”；包含数字冲突的中文也不会被悄然放行；如果模型返回 HTTP401/403/429/500、用户取消或网络故障，则仍作为真正服务错误处理，不吞掉日志、不自动切换服务。
6. 长视频每次请求后保存有效行、失败次数与未译回退 ID；同源同模型同范围续跑可复用。r23 的有效译文继续保留，旧版耗尽的四次尝试会被重置为新版策略计数，不需要清空缓存。

**内容质量边界**：这是一种自动恢复流程，不是“AI 自动证明译文正确”。语言、结构和数字检查只能排除部分明显错误。不能因用户不进行人工验收就宣称已核实语义；如果模型始终无法翻译，最终文稿会含有明确标记在详情中的原文片段，而非杜撰中文。

## 安装和使用

1. 停止当前生成，备份 `D:\VideoKnowledge_Git_Project`。不要删除扩展/重新安装扩展。
2. 把 ZIP 内 `VideoKnowledge_Git_Project` 文件夹内容合并到现有工程目录，仅覆盖源代码。保留 `.venv`、`.venv-qwen`、`models`、用户音频/SQLite/笔记、私有配置和已有扩展身份。
3. 在 Edge 的 `edge://extensions` 重新加载**原已加载**的 VideoKnowledge 扩展，刷新视频页面。
4. 对同一视频、相同模型和整理范围重新选择「文字稿」→生成。r23 已经存储的成功译文复用，之前失败条目按新策略自动处理。
5. 如仍有外文出现在结果里，可以查看生成结果“详情”中的自动回退说明，无需人工审批；如是 403/500，请优先处理模型服务本身的访问与稳定性。

本轮只修改浏览器扩展的翻译路线和测试/版本记录。无需重装 Ollama/Sherpa，本地语音服务启动脚本不变。

## 回退与验收

- 回退时停止正在进行的生成，将备份的 r23 源码覆盖回原目录并重新加载原扩展。不清除任何数据库、缓存或音频。
- 自动化验证包含：部分译文保存、缺少 ID 重试、单条普通中文响应、阿拉伯数字改变拒绝、所有请求无效但整份稿能完成并记录原文、旧 r23 计数迁移、长视频检查点续跑、HTTP500 不中断原有检查点保护。
- 尚未在用户 Windows、Edge、真实 Ollama 模型和两小时视频上执行原生端到端验证；需要现场观察实际输出与速度。

## Git 提交示例 (PowerShell)

```powershell
cd D:\VideoKnowledge_Git_Project
git status
git add -A
git diff --cached --check
git commit -m "fix: automatically recover incomplete transcript translation without manual gating"
git push
```

提交前检查不要包含虚拟环境、原音、音视频缓存、数据库、日志、密钥或私人笔记。
