# git-r25 升级说明 · 文字稿西语/中文混排与漏译校验修复

## 现场问题与代码原因

用户提供的输出中，一段关于 Sergio Marina 的发言前半部分仍是西班牙语，末尾突然接中文；Google 翻译可以将同一来源译成连贯中文。r24 的 `isChineseTranslation` 只要求汉字占全部字母至少 20%，这样“长段外语+一小段中文”的模型返回值仍可能通过校验，作为成功译文保存。另一个来源是上游 ASR 将部分中西混合译文标为 `translationStatus=done`，文字稿会直接沿用；而分段翻译失败时，原文段与已翻译段在拼合时可能没有清晰的边界。

不能根据图片断言究竟是 ASR、翻译模型还是缓存中的哪一个环节造成了该条具体记录，三条路径均纳入本次修复。

## r25 修改

1. **外语残留检测**：译文必须含中文，且不能含明显长段西语/英文等拉丁字母自然语句，也不能包含大量其他未翻译文字；保留 `Sergio Marina` 等短专名不报错。对较长、词汇变化丰富的原文，检查是否被过度压缩成极少中文；这是保守的完整性启发式，不等于语义准确率检测。
2. **ASR 已完成标记纠正**：如果 ASR `done` 结果仍夹有大片外语，且保存了独立原文，文字稿阶段将原文送给本地翻译模型重新翻译。原始记录不覆盖；手动修改内容保持优先。
3. **失败自动补译**：沿用 r24 8→4→2→1 条缩小请求，最终单条自由中文返回。对外语残留拒绝复用，不要求人工点击核查。译文始终无效时保留该原文且在生成详情标为自动翻译未完成，绝不称作“全部已翻译”。
4. **升级旧检查点**：翻译策略版本由 2 更新至 3；旧版自称成功的行重新验证，旧版兜底外语和耗尽的重试次数重新处理，原有效中文译文可复用。翻译修正后，比对断句缓存的原文非标点内容，发现变化时重做该断句批次。旧历史文稿、笔记及音频不删除。
5. **防止错拼接**：如仍有个别未翻译分片，分片交界处使用换行，不能把 `guiando` 与相邻中文直接拼成一个词；生成详情继续注明未译片段。

## 范围与限制

- 不会自动调用 Google 翻译，也不上传视频内容到第三方翻译服务；继续使用用户配置的模型和授权范围。
- 未声称 AI 能证明语义完全忠实：数字保护和外语残留只是可程序验证的部分。罕见长专名或被引用的外语原句可能触发额外重译，未达到翻译条件的模型仍可出现保底原文。
- 不更换 Ollama/Sherpa、不修改 ASR 服务，不删除旧缓存；不解决上游模型服务 HTTP 403/500。
- 测试基于 Linux 的模拟模型/浏览器，尚未在用户 Windows+Edge+真实 Ollama+两小时视频现场验收。
