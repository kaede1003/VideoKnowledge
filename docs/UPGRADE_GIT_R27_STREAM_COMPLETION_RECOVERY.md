# git-r27 · 长文 AI_STREAM_INCOMPLETE 流结束识别与本机自动恢复

## 现场问题与根因

用户升级 r26 后，插件提示 `AI_STREAM_INCOMPLETE：模型连接结束，但没有完整结束标志`。定位到 `extension/longform-background.js`：旧逻辑以 SSE `\n\n` 为唯一事件边界，未处理 EOF 时无最终空行的完整帧，也不接受只有 `finish_reason=stop` 而未提供 `[DONE]` 的显式终止。更重要的是，当服务器真的关闭连接、未提供任何终止证据时，旧版会立即中止，无法自动恢复当前分片。

**明确界限**：截图能证明插件没有收到结束标记，但不能证明是 Ollama 推理异常、网络中断、插件流解析问题还是代理截断。没有用户本机模型日志，不声称已修复 Ollama 的上游故障。

## r27 行为

1. **解析更完整**：SSE 事件跨多个网络数据包、中文 UTF-8 字节跨包、`\r\n`/`\n`、心跳注释及 EOF 最后一帧无空行，均按协议解析。支持显式 `finish_reason=stop` 和 `[DONE]`；不把单纯 TCP EOF 当作完成。
2. **本机一次自动恢复**：流结束时若确实既没有可信终止标记，又检测为本机 `127.0.0.1:11434` 或 `localhost:11434`，会用**同一模型、同一输入、同一 token 配额**请求一次 `stream:false`，只使用重取返回的完整 JSON 正文；**丢弃此前流中的半截内容，不拼接两次回复**。读取中断、末尾不合法事件亦采用此路径。
3. **有限保护**：非流式恢复与首次流共享同一总计时上限；不无限重试。不自动更换模型/服务，也不重新下载模型。自定义远程服务不会偷偷重发可能收费的请求。
4. **严格完成门禁**：`finish_reason=length` 仍视为输出截断，按已有 r22 自适应原始来源分块处理；`content_filter`、`tool_calls` 等不能算作完成正文。响应始终缺少结束证据或恢复 HTTP 500 时，任务留在可续跑检查点，不发布半截稿件。
5. **验证真实流路径**：「保存并验证」仍要求 `stream:true` 本身正确结束，**不**通过非流式兜底假装流式验证成功；普通长文生成和外语文字稿则可使用本机自动恢复。

## 升级（保留所有数据）

1. 停止正在生成的任务；建议先备份 `D:\VideoKnowledge_Git_Project`，尤其备份原有数据目录与本地配置。
2. 将 r27 ZIP 中 `VideoKnowledge_Git_Project/` 下的源码文件按相同目录结构覆盖至原工程；不要删除或覆盖用户自己的 `.venv`、模型、SQLite、音频、笔记或私人设置。
3. Edge 打开 `edge://extensions`，重新加载原来已经安装的 VideoKnowledge 扩展，不要先卸载扩展或清除扩展数据；刷新视频页面。
4. 在设置页执行「保存并验证普通/长文请求」，确认流式通道可完成。然后对原来失败的视频、同一模型和相同整理范围重新点击「生成」，复用之前已完成的检查点。
5. 若仍出现错误：保存插件最终提示，查看 `%LOCALAPPDATA%\Ollama\server.log` 同时间段错误（可隐藏隐私和 token），确认是否有 runner 退出、EOF、显存不足或服务返回 HTTP 500。若使用自定义提供方，检查其是否返回符合 OpenAI 格式的终止事件。

## 回退与数据保护

- 保留旧版 r26 工程 ZIP 或备份。需要回退时恢复 r26 源码并重新加载 Edge 扩展。**不要清空扩展本地存储。**
- 本版没有更换数据库结构或检查点 schema，不会删除旧生成结果/原始音频。已经导出的历史文稿不会自动重新生成。
- 保留原有 r22–r26 自适应切分、翻译、角色命名和进度功能。

## 验证边界

新增合成 SSE/HTTP 断流、单次非流式恢复与检查点复用回归。真实 Windows + Edge + 本机 Ollama + 两小时视频在此环境尚未验证；若模型服务本身崩溃、HTTP 500 或模型根本无法生成完整内容，客户端不能保证自动恢复成功。
