# git-r23 · 长视频进度面板与文字稿漏译补译

## 修复问题

此前 r22 的后台每处理一个新的模型请求，就会从持久检查点重新读取已完成批次。`longform-background.js` 在**回放这些已经完成的批次时仍发送进度消息**，造成“第 1 / 148 批”快速跳回“第 55 / 148 批”。`content.js` 则在每一条进度消息到来时调用完整 `render()`，进一步干扰页面，且仅显示一行跳动的文字。

## 文字稿 `AI_TRANSLATION_INVALID`（本轮追加修复）

- **根因**：文字稿翻译一次请求中只要漏掉一条 ID，旧代码就拒绝整批译文；长视频上的有效译文无法在此类响应后被保留。
- **新策略**：按原 ID 验证每一条译文，保留中文与原文字数/数字等检查合格的行；漏掉、重复 ID、未翻译成中文、数字冲突或 JSON 不完整时，只重试未通过的行。重试批次从最多8条逐级缩为4、2、1条，每条最多尝试4次，避免无限重试。
- **长视频检查点**：每次翻译请求后，已验证译文和每条重试计数分别记录在同一视频与输入指纹的分片检查点中；任务在 HTTP500 或扩展工作进程接力时失败，重新选择原视频同模式、同模型、同范围可复用已成功行。
- **安全与质量**：不把外文原话冒充中文译文、不跳过未译条目；连续失败时显示剩余缺项并保留原始记录与旧成稿；401/403/429/5xx 不盲目重试。只校验 ID、中文比例、数字等可程序验证条件，无法保证译文语义正确。

## 进度面板改动

- **修复事件来源**：仅在真正开始一条新的模型请求时通知进度；读取旧检查点不再重播进度消息，分段继续时不虚报尚未开始的后续批次。
- **固定高度进度面板**：显示正在整理的视频标题、当前阶段及阶段编号、已完成批次数、正在处理的批次和当前阶段进度条。跨章节主题合并/全局索引有多轮处理，明确显示“第 N 轮”。
- **不虚报总进度**：进度条是*当前阶段*的批次进度（例如已完成54/148批是36%），并不是全视频的全流程百分比，也不承诺预计完成时间。生成的新阶段/新一轮会明确更换阶段标签并从新的批次进度开始。
- **轻量更新**：后台进度事件只更新任务面板，不重新绘制整份历史转写、角色和报告预览；旧的异步迟到事件通过请求ID隔离；面板收起后任务仍然在该视频页运行，重新展开可看到进度。
- **Edge 工具栏角标**：正在生成的标签页显示 `AI` 角标，悬停可查看视频标题、阶段、当前批次。角标按标签页隔离，成功/失败/取消时清除。仅使用 `chrome.action` 现有权限，不添加 Windows 常驻程序。
- **知识整理主算法不变**：r22 的自适应分块与主题合并不变；仅增加文字稿模式的部分译文保存与补译。没有删除旧文稿、记录、缓存或模型。

## 升级操作

1. 停止正在运行的长文整理；**不要在生成过程中覆盖扩展代码**。已有检查点会保留。
2. 备份 `D:\VideoKnowledge_Git_Project`，将本包内 `VideoKnowledge_Git_Project` 的源码按原目录覆盖；保留本地 `.venv`、`.venv-qwen`、`models`、音频缓存、SQLite、用户笔记、私有设置与 API Key。
3. 打开 `edge://extensions`，对原 VideoKnowledge 扩展点击“重新加载”，**不卸载/重装**；刷新原视频标签页。
4. 选同一视频、整理模式、时间范围和模型重新点击“生成整理”。既有持久检查点（包括 r22 完成的翻译批次）仍可复用；新产生的部分译文检查点也能续跑。展开或收起插件面板时可查看任务情况。
5. 若把插件图标固定到 Edge 工具栏，正在生成时会看到 `AI` 角标。**悬停**图标查看进度与视频标题；目前单击扩展图标仍保留原来的听写快捷操作。

不需要重新安装/升级 Ollama、Sherpa 或 ASR 服务；本版主要修改浏览器扩展代码。

## 限制和回退

- 纯浏览器扩展无法直接增加 Windows 系统托盘图标。若要原生托盘功能需要单独安装、授权并维护 Windows 常驻程序，本版不增加这些系统级权限。
- 当前面板收起（未刷新页面、未关闭标签）会继续执行；**关闭或刷新视频标签可能中断页面驱动的后台接力**。下次重新打开相同视频、范围和模型可根据已完成检查点续跑；本版不承诺关闭浏览器后仍独立运行任务。
- 模型重试、实际拆分级数和将来主题合并轮数不可事先准确预测，所以不显示虚假的整体完成百分比或剩余时间。
- UI/事件测试及翻译补译回归使用 Linux + Chromium/模拟 Ollama；仍需目标 Windows + Edge + 真实两小时外语视频实测进度、中文质量、耗时与失败恢复。
- 已成功翻译的中文仍可能存在专名、否定、数字文字表达等语义错误，机器的结构校验不能替代原语音核对。
- 回退：停止整理，将之前备份的 r22 **源码**覆盖回原目录，再重新加载原扩展。不要删除原文、检查点或用户数据。
