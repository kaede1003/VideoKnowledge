# 内容筛选实现约束

音频采集与持久化保持原链路。每批已转写文字先存储，再投影出筛选视图；阶段摘要、本地关键句和知识生成在调用模型之前选择输入。筛选不会删除原始字段、角色或时间戳。

## 两种轴与第三种未知

- 质量轴：unknown / review / human_edited。字词分数低于0.55、既有质量标记、异常长重复等只是工程规则，不输出“X%正确”。
- 主题轴：unknown / on_topic / supporting / off_topic / promotion / uncertain。只允许本地模型在当前文本版本、当前主题上做有依据的排除建议。self certainty是模型自评，不是统计校准值。
- 事实真假：没有自动判定；仍应将讲述者观点与已验证事实分开。

## 数据

`contentFilter={enabled,topic,semantic}`；`filterOverrides={cue_key:keep|exclude}`；`filterAssessments={cue_key:{label,certainty,evidence,reason,fingerprint,topicKey,model}}`。用户决定优先；版本摘要防止把旧主题判定施加到新内容。所有这些都是原文旁路数据。

`screeningCues`返回完整decisions及include/hold/exclude数量。并非一个坏分数删除整句原文；hold只是不作为新知识摘要的证据。模糊主题宁可include。生成结果记录筛选数量；旧结果是不可变快照。

知识模式与其他四种模式不同：其他模式的自动规则不删除剧情/对白，只加疑点；人工exclude仍生效。规则只保护已实现的信号，不保证对全部语言/引用/双关的识别。

## 模型负载

默认不调用模型。可选分类在活动录制时每60秒最多10条，文本正文4200字符左右、邻句上下文有界，最多1200输出token、25秒请求时限；失败后延后约3分钟。既有后台AI作业繁忙会延后，用户主动生成前请求取消分类。模型缓存按文本修订与主题版本复用。分类失败不改写或删除任何原文。

浏览器后台/操作系统完全停顿时没有硬实时保证。Python端翻译、视觉任务与浏览器的推理工作不在同一个全局队列，不能承诺全局GPU无竞争。

## 审计与恢复

主UI默认收起原文和筛选详情。可对原文按时间回看、逐条指定纳入/排除/自动；关闭开关停止应用所有排除。导出JSON保留原文与旁路选择。旧文档和旧阶段摘要不会自动重写，需要主动重新整理。
